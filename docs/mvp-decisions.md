# NeedToBuy — решения по MVP

Зафиксировано по итогам grilling-сессии от 2026-08-19.

## Продукт

Веб-сервис для родителей (и их близких) — что купить ребёнку по возрасту
(одежда, игрушки, книги, спортинвентарь). Родитель заводит профиль ребёнка
и личный вишлист. Есть общий курируемый каталог-рекомендатель по возрастным
диапазонам. Товары в каталоге — не карточки конкретных товаров, а текстовые
идеи со ссылкой на поисковую строку маркетплейса. Дарители (родственники/
друзья) открывают вишлист родителя по ссылке.

## Сущности и роли

- **Личный вишлист родителя** — свободный, без модерации.
- **Общий эталонный каталог** — ИИ-подбор + модерация. Единственный
  модератор на MVP — Карина (единолично, без ролей/команды), работает через
  встроенную админ-панель (защищённый роут в приложении, не полноценная
  админка с ролями). Генерация ИИ-предложений — вручную по запросу: диапазон
  + категория → «сгенерировать» → одобрить/отредактировать/отклонить.
- **Родитель** — первый пользователь, владелец профиля.
- **Даритель** — заходит по публичной ссылке на вишлист, без регистрации.
- Бронирование подарков (registry-фича «занято/забронировано») — **не
  делаем на MVP**, слишком рано.

## Возрастная сетка

- 0–6 мес. — помесячно
- 6–18 мес. — по 3 мес.
- 18 мес.–3 года — по полгода
- 3–12 лет — погодично
- 12+ — единая корзина без дальнейшего дробления

Сетка захардкожена в коде (константы/enum), без БД-таблицы и без админки
для её редактирования.

## Гео и маркетплейс

- Гео — Россия.
- На старте — только Ozon (единственная партнёрка без порога по трафику;
  WB — статус спорный, Яндекс Маркет требует уже 1000+ визитов/день).
- У маркетплейсов нет открытого bulk-API — ручная/ИИ-курация с модерацией
  неизбежна.

## Монетизация

Выключена на MVP, но архитектурно закладываются все три рычага:
- affiliate-трекинг в ссылках,
- поле «уровень доступа» под будущую подписку,
- место под спонсорские размещения брендов.

Юр.форма для приёма выплат Ozon-партнёрки (ИП/самозанятость) — решается
позже, не блокирует MVP.

## Авторизация

Email + одноразовый код подтверждения (OTP), без пароля, без SMS.
Соц.вход (VK ID / Яндекс ID) — в бэклог, добавляется позже.

OTP выбран вместо magic-link: аудитория часто открывает почту на одном
устройстве, а сайтом пользуется с другого — код работает независимо от
устройства, ссылка — нет.

## Технологический стек

- **Бэкенд**: Go, JSON REST API (`net/http` + `chi`, без тяжёлого
  фреймворка). API-first с самого начала.
- **БД**: PostgreSQL.
- **Фронтенд (веб)**: React + TypeScript, SPA (Vite), общение с бэкендом
  только через JSON API.

API-first выбран сознательно: платформа на MVP — веб (не мобильная), но
в будущем планируется полноценное приложение за пределами веба. Общий API
позволит подключить мобильного клиента позже без переписывания бэкенда.

## Комплаенс

- 152-ФЗ — согласие родителя на обработку данных ребёнка чекбоксом при
  создании профиля.
- Маркировка рекламы (erid/ОРД) для партнёрских ссылок — учитывается
  позже, при включении монетизации.

## Осознанно отложено (не блокирует MVP)

- Бронирование подарков / registry-фича.
- Юр.форма для выплат Ozon-партнёрки.
- Маркировка рекламы (erid/ОРД).
- Мобильное приложение (API уже готовится под него).
- Соц.вход (VK ID / Яндекс ID).
